# BPVS server v2 — standalone MongoDB

Node 22+, Express 5, MongoDB standalone. Password-only login, bearer JWT and rotating refresh tokens. No OTP enrollment endpoint, cookies or database transactions. Existing API routes otherwise retained. Use `.env.example` as a template, preserve existing secrets and QR keys when migrating. Generate two independent secrets with `node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"`. Set ADMIN_EMAIL and ADMIN_PASSWORD (12+ characters). Run npm install, npm run keys (only for new key directory), npm run seed, npm run dev. Health: /api/v1/health. Login POST /api/v1/auth/login with email/password returns accessToken, refreshToken, expiresIn. Existing frontend must be updated to remove OTP UI.

Standalone tradeoffs: registration compensates failed user creation where possible; process crashes can leave pending orphan manufacturers. Batch review locks edits before preparing a unique QR; retry review if preparation fails; QR download requires approved batch and manufacturer. Concurrent reviews use conditional status updates. Rejected batches may retain inaccessible prepared QR records. Print logs use unique event IDs and recompute cumulative counts; retry same event ID after failure. Audit and approval/notification writes are not atomic with primary records; audit failures are logged. Refresh failure may require login again. Manual reconciliation may be necessary after crashes. Do not treat as production-ready. Physical anti-copy, offline verification and complete TOR reports remain incomplete. Password-only login deviates from TOR 2FA requirement.

Restore MongoDB service to its working standalone configuration before running. Do not delete data or regenerate existing QR keys. Back up database and configuration before migration. No full integration test performed.
